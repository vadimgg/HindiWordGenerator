# Research

## Files

### `docs/DESIGN.md`

#### R001 - Source Identity Contract Already Exists

Status: confirmed
Kind: implementation
Backlog: none
Confidence: high

What we saw:
- The design defines file-scoped IDs, says IDs are stable strings, and names
  `source_ref.file + source_ref.item_id` as the source row identity.

Why it matters:
- M1.5 should implement this contract directly instead of inventing another ID
  shape.

Recommended action:
- Use quoted zero-padded numeric strings such as `"0001"`.

### `docs/ROADMAP.md`

#### R002 - M1.5 Is A Discrete Milestone

Status: confirmed
Kind: workflow
Backlog: none
Confidence: high

What we saw:
- Roadmap lists M1.5 between the M1 doctor skeleton and M2 sentence planner.
- It explicitly says old output is not modified and lineage is not backfilled.

Why it matters:
- The migration can be implemented and reviewed independently from planner
  behavior.

Recommended action:
- Keep protected paths around `output/`, `audio/`, and archived legacy input.

### `input/sentences/*.yaml` and `input/words/*.yaml`

#### R003 - Active YAML Items Currently Have No IDs

Status: confirmed
Kind: data
Backlog: none
Confidence: high

What we saw:
- Active YAML files contain `title`, `subtitle`, and `items` with `hindi`,
  `romanisation`, and `english`, but no `id` fields.

Why it matters:
- M2 cannot validate source item IDs until this migration runs.

Recommended action:
- Add IDs across both sentence and word source files.

## Data Drift Themes Caught

- Source identity must be attached to active YAML only; archived CSV files are
  historical inputs and should not be used as fallback authority.
- Old accepted output stays lineage-less until regenerated by future Rust
  flows.

## Research Decisions

- The migration command should touch both sentence and word YAML because M1.5
  is about source identity, not sentence generation only.
